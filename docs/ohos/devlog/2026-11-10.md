# 2026-11-10 · 后端方案定型，D⁺ 的传输打通

## 今天定的事

1. **排除 web**：ArkWeb + wasm 出局——用 MyGo 的理由就是不用 WebView。
2. **排除"Go 引擎 + ArkTS 界面"**：等于重写视图层。
3. **排除进程内 cgo**：框架里不能出现 `import "C"`。MyGo 的理念是"Go 不依赖 cgo
   编译机制"，不是"不许有 C"——SQLite/Zig、Terminal/Ghostty 都是原生库、purego 加载。
   注意方向：原生模块机制是 **Go → C**，方案 C 需要 **C → Go**，机制表达不了。
4. **定为 D⁺**：出进程 + 缓冲区 fd 直传。理由是它同时满足"不 web、复用 `ui`、
   零 cgo、零拷贝"，且不像 E 那样需要 parcel 和跨进程句柄引用计数。

细节见 [../design/d-out-of-process.md](../design/d-out-of-process.md)。

## 读到的关键事实（都有出处）

| 事实 | 出处 |
|---|---|
| `surfaceId` 反查 surface 不能跨进程 | `capi-external-window-h.md:880` |
| `OH_NativeWindow_WriteToParcel/ReadFromParcel` 是 API 12，属正常用法 | `capi-external-window-h.md:994,1023`、`native-common-mistakes.md:26` |
| `OH_NativeBuffer_WriteToParcel/ReadFromParcel` 是 API 23 | `capi-native-buffer-h.md:544,573` |
| `BufferHandle` 有 `fd/stride/size/virAddr`，共 64 字节 | `capi-nativewindow-bufferhandle.md` |
| `FlushBuffer` 的 Region 以**左下角**为原点，`rectNumber≤0` 即整屏 | `capi-external-window-h.md:417` |
| `UnlockAndFlushBuffer(window)` 不接 region，脏区只能在锁时给 | `capi-external-window-h.md:1273` |
| `AbortBuffer` 能把 buffer 还回队列 | `capi-external-window-h.md:483` |
| `module.json5` 的 `srcEntry` 只能是 `.ets` | `module-configuration-file.md:282` |

**因此主路径用 `RequestBuffer` + `FlushBuffer(region)`**（region 在提交时给，匹配
`internal/raster` 的 damage），而不是 `LockBuffer` 那一对。

## 今天跑通的：`experiments/ohos-frame`

一个嵌套模块，两个进程，一条 `AF_UNIX` 流，一个共享缓冲区文件代替图形 buffer。
宿主用 `SCM_RIGHTS` 把 fd 交给引擎，引擎 `mmap` 后只画脏矩形，宿主校验。

```
$ go test ./...
ok  ohosframe/internal/proto

$ ./.bin/ohosframe-host -engine ./.bin/ohosframe-engine -w 640 -h 480
surface 640x480 stride 2560 size 1228800
engine pid 20081
SURFACE -> engine, fd 3 passed
FRAME_READY seq=1 rects=1 ui=[{80 60 160 120}] flush_region=[{80 300 160 120}]
pixels: 307200 checked, 0 wrong
PASS
```

注意 `ui → flush_region` 那一行：`60 + 120 = 180`，`480 - 180 = 300`。左下原点的
转换在这里被验证了一次（`proto.Flip` 翻两次必须回到原处，有单测钉住）。

> 这台机器 `/tmp` 是 `noexec`，产物要放在工作区（`.bin/`，已 gitignore）。

## 明天

P0-3 三件事，任何一件不成立就改变方案：

1. 应用进程里自己 `fork+execve` 是否被允许（zcode 只证明了 Chromium 的 `posix_spawn` 行）；
2. 私有 HNP 里的 ELF 能否执行；
3. 图形 buffer 的 fd 能否跨进程 `mmap`——**这条决定了 D⁺ 还是退回 memcpy 版 D**。

前两件可以直接写一个 20 行的宿主 + 一个空转的引擎去撞；第三件要真机 + `RequestBuffer`。
